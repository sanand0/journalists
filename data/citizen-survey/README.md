# Citizen Survey 2022–23 — Data Workspace

This directory contains the raw data, conversion scripts, verification scripts, and analytical insights for the **Lancet Citizens' Commission Citizen Survey 2022–23** — a large-scale, multi-state survey on health-seeking behaviour, out-of-pocket expenditure, insurance coverage, and primary care preferences across India.

The README starts with the data itself. Scripts and usage come after.

---

## Data Overview

**Source:** Lancet Citizens' Commission on Reimagining India's Health System  
**Survey period:** December 2022 – January/February 2023 (field dates in `date_of_interview` encoded as DDMMYYYY)  
**Coverage:** 50,217 respondents · 29 states · 130 districts · 934 blocks  
**Residence split:** Rural 70.2% (n=35,255) · Urban 29.8% (n=14,962)  
**Age range:** 15–72 years · Median age 37  
**Gender:** Male 56.1% (n=28,154) · Female 43.5% (n=21,840)

## Quick Start

**Download the ZIP from Harvard Dataverse and convert to Parquet + Excel:**

```bash
uv run 01_download_and_prepare.py
```

Re-running skips the download if the ZIP is already present, and skips conversion if both outputs exist. Force flags:

```bash
uv run 01_download_and_prepare.py --force            # re-download + reconvert
uv run 01_download_and_prepare.py --force-download   # re-download ZIP only
uv run 01_download_and_prepare.py --force-convert    # reconvert from existing ZIP
```

**Verify all card numbers against the raw data:**

```bash
uv run 02_verify_cards.py
```

Verify a single card, or with looser tolerance:

```bash
uv run 02_verify_cards.py --card 1
uv run 02_verify_cards.py --tolerance 0.02
```

Both scripts use PEP 723 inline metadata (`# /// script`) so `uv run` installs dependencies automatically.

## Critical Data Pitfalls

These are the most common errors when working with this dataset. Each caused a failing verification check before being caught.

1. **`b1_most` and `b7_1` use different provider numbering.** AYUSH is 9 in `b1_most` but 8 in `b7_1`; TradHealer is 10/9; Chemist is 11/10. Never compare them directly. Always apply the `B1_TO_B7` crosswalk in `02_verify_cards.py`.

2. **`c1_most` inpatient codes differ from outpatient codes.** Govt Hospital = **3** (not 5), Private Hospital = **5** (not 7). Using the outpatient codes for inpatient analysis swaps all rows.

3. **Net-change computation for Card 01 requires filtering to rows where BOTH `b1_most` and `b7_1` are valid.** The correct denominator is n=41,659, not n=41,835 (all outpatient rows). The 176-row difference (DNA/Other on `b7_1`) shifts all net-change values.

4. **`rec_a2d` is the recoded education variable.** Raw `a2d` has 8 categories. Card 05 uses the recoded 4-group version. Never filter on raw `a2d` values when the analysis calls for `rec_a2d`.

5. **Use median not mean for food/OOPE metrics.** Both `a2g_food` and `oope_total_ip` are right-skewed and recall-rounded. Means are inflated; medians are the correct centrality measure for these story contexts.

## Data Caveats

- **Recall-based expenditure.** 99.8% of `a2g_food` values are multiples of ₹100. OOPE figures are rounded and self-reported.
- **Stated vs revealed preferences.** Section B/C captures actual provider use for one specific episode. Section D captures stated preferences. These are different constructs and cannot be compared as rates of the same thing.
- **Cross-sectional.** The survey is a single point-in-time snapshot. No causal inference is valid from associations in this data.
- **Doctor-Mobile Van gap.** The 252 respondents who used a Doctor-Mobile Van (b1_most=8) have no equivalent code in `b7_1`. Their current-use counts cannot be tracked to a preferred-next equivalent.
- **Unequal state sample sizes.** Uttar Pradesh (n=5,601) has more than double the respondents of several smaller states. State-level comparisons should account for sample size differences.
- **`any_insurance` derived flag.** Insurance coverage in this dataset means "any of four schemes" — it is not disaggregated by benefit cap, scheme generosity, or claim history.
